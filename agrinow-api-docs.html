1. Overview & Authentication

Base URL All endpoints are relative to your deployment URL, e.g. https://api.agrinow.in. In development, this is typically http://127.0.0.1:8000.
How Authentication Works 1. Call POST /auth/login with credentials.
2. The server sets an HTTP-only cookie (access_token) and also returns the JWT in the JSON response body.
3. For every subsequent request, either:
  • The cookie is sent automatically by the browser (recommended), or
  • Set the header Authorization: Bearer <token> manually (for mobile / non-browser clients).
4. The JWT expires after 60 minutes. Re-login to get a fresh token.
Roles The API enforces role-based access. The possible roles are: admin, manager, farmer, agent, analyst.
The JWT payload includes a role field — read it after login to redirect users to the correct dashboard.
Zero-Knowledge Password Scheme Passwords are never stored. The server derives a 32-byte master key from the password via Argon2id, then uses it to decrypt an Ed25519 private key stored in a separate Supabase vault. A successful decryption proves the password is correct. This means password reset cannot reveal the old password — it generates entirely new keys.

2. Authentication — /auth

Handles login, logout-cookie clearing, and the full password lifecycle.

POST /auth/login Public

Authenticate user and issue JWT

Validates credentials using the zero-knowledge flow. On success, sets an HTTP-only cookie access_token and returns a JSON body with the token and user metadata. If the account is inactive, returns 403. Wrong password returns 401.

Request Body (JSON)

FieldTypeRequiredDescription
identifierstringRequiredUsername or email address
passwordstringRequiredPlaintext password — stretched via Argon2id, never stored

Example Request

{
  "identifier": "john_doe",
  "password": "MySecureP@ssw0rd"
}

Success Response — 200 OK

{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer",
  "username": "john_doe",
  "email": "john@example.com",
  "role": "farmer"
}

Status Codes

200 OK — Login successful 401 Invalid credentials 403 Account inactive 404 User not found 500 Server misconfiguration
POST /auth/forgot-password Public

Request a password reset email

Sends a one-time reset link (valid 15 minutes) to the user's registered email. Always returns the same success message regardless of whether the email exists, to prevent user enumeration.

Request Body (JSON)

FieldTypeRequiredDescription
emailstring (email)RequiredRegistered email address

Example Request

{
  "email": "john@example.com"
}

Success Response — 200 OK

{
  "message": "If an account with that email exists, a reset link has been sent."
}
Frontend Note Always show this exact message to the user — do not conditionally show success/error based on the response. This is a security requirement to prevent user enumeration.

Status Codes

200 OK — (always, even if email not found)
POST /auth/reset-password Public

Reset password using a valid one-time token

Validates the UUID token from the reset email link, generates a completely new Ed25519 key pair derived from the new password, and updates both the primary database and key vault. The token is single-use and expires after 15 minutes.

Request Body (JSON)

FieldTypeRequiredDescription
tokenstring (UUID)RequiredThe reset token from the email link query param ?token=…
new_passwordstringRequiredNew password (min 6 characters)

Example Request

{
  "token": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "new_password": "NewSecureP@ss99"
}

Success Response — 200 OK

{
  "message": "Password has been reset successfully. You can now log in with your new password."
}

Status Codes

200 OK — Password reset successfully 400 Invalid / expired / already-used token 500 Key vault error
POST /auth/change-password Requires JWT

Change password for the currently authenticated user

Verifies the current password, then re-keys the user's cryptographic identity with the new password. The user must be logged in (valid JWT). Returns 401 if the current password is wrong.

Request Body (JSON)

FieldTypeRequiredDescription
current_passwordstringRequiredThe user's existing password for verification
new_passwordstringRequiredNew password (min 6 characters)

Example Request

{
  "current_password": "OldPassword123",
  "new_password": "NewPassword456!"
}

Success Response — 200 OK

{
  "message": "Password updated successfully."
}

Status Codes

200 OK — Password changed 401 Current password incorrect 404 User not found 500 Key vault error

3. User Management — /create_user & /users

Create, read, update, and delete user records. Most endpoints require a valid JWT. User creation is restricted to admins.

POST /create_user/ Admin Only

Creates a new user with zero-knowledge key generation. Only users with the admin role can call this endpoint. A welcome email is sent to the new user. Returns the created user profile — no sensitive data is included.

5. Images — /images

Upload, list, and retrieve images stored as BLOBs in the database. Pillow compression is applied automatically on upload.

Thumbnail Strategy On upload, the server automatically generates a 256×256 base64 thumbnail stored separately. Use GET /images/base/{id} for fast previews (e.g., in chat or lists) and GET /images/{id} only when full-resolution display is needed.
POST /images/ Requires JWT

Upload & compress an image

Accepts a multipart/form-data upload. Compresses the image in-memory (JPEG q90, PNG lossless, WebP q90), stores the BLOB, generates a 256×256 thumbnail, and returns metadata. Supported formats: JPEG, PNG, WebP, GIF.

Request — multipart/form-data

FieldTypeRequiredDescription
fileUploadFileRequiredThe image file (JPEG, PNG, WebP, GIF)

Example — JavaScript Fetch

// Upload an image file from an <input type="file">
const formData = new FormData();
formData.append('file', fileInputElement.files[0]);

const resp = await fetch('/images/', {
  method: 'POST',
  headers: { Authorization: `Bearer ${token}` },
  body: formData,
});
const meta = await resp.json();

Success Response — 201 Created

6. Error Reference

All errors are returned as JSON with a detail field. Standard HTTP status codes apply.

HTTP StatusWhen It OccursWhat to Show the User
400Invalid/expired/used reset token; image compression failedShow the error detail message directly
401Wrong password; invalid/expired JWT"Invalid credentials" or redirect to login
403Account inactive; insufficient role"Your account is inactive" or "Access denied"
404User, site, image, or assignment not found"Not found" message or empty state UI
409Duplicate username or email on user creation"Username or email already exists"
422Pydantic validation error — missing/wrong field typesHighlight the specific invalid field
500Server misconfiguration; key vault unreachable"Server error — please try again later"

Error Response Shape

{
  "detail": "A user with this username or email already exists."
}

7. Quick-Start Code Snippets

Copy-paste examples for the most common frontend flows.

1 — Login & Store Token

// JavaScript (fetch) — works with cookie or manual Bearer
async function login(identifier, password) {
  const res = await fetch('/auth/login', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    credentials: 'include',  // important: sends/receives HTTP-only cookie
    body: JSON.stringify({ identifier, password }),
  });
  if (!res.ok) throw new Error((await res.json()).detail);
  const data = await res.json();
  // data.access_token, data.role, data.username, data.email
  localStorage.setItem('agrinow_token', data.access_token);
  localStorage.setItem('agrinow_role',  data.role);
  return data;
}

2 — Authenticated Request Helper

// Reusable helper — automatically attaches the Bearer token
async function apiFetch(path, options = {}) {
  const token = localStorage.getItem('agrinow_token');
  const res = await fetch(path, {
    ...options,
    credentials: 'include',
    headers: {
      'Content-Type': 'application/json',
      ...(token ? { Authorization: `Bearer ${token}` } : {}),
      ...options.headers,
    },
  });
  if (res.status === 401) {
    // Token expired — redirect to login
    window.location.href = '/login';
    return;
  }
  if (!res.ok) throw new Error((await res.json()).detail);
  return res.json();
}

3 — Upload an Image

// multipart/form-data — do NOT set Content-Type manually
async function uploadImage(file) {
  const token = localStorage.getItem('agrinow_token');
  const form = new FormData();
  form.append('file', file);
  const res = await fetch('/images/', {
    method: 'POST',
    headers: { Authorization: `Bearer ${token}` },
    credentials: 'include',
    body: form,
  });
  if (!res.ok) throw new Error((await res.json()).detail);
  return res.json(); // { id, file_name, format, size, created_at }
}

4 — Post a Site Comment with Image

// 1. Upload image first, get the image_id
const { id: imageId } = await uploadImage(myFile);

// 2. Post comment referencing the image
const comment = await apiFetch('/sites/comments', {
  method: 'POST',
  body: JSON.stringify({
    site_user_relation_id: 12,
    comment: "See attached photo.",
    image_id: imageId,
    type: "image",
  }),
});
